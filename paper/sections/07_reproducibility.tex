\section{Reproducibility}
\label{sec:reproducibility}

\paragraph{Code and dataset release.}
Code, dataset, and analysis scripts are released as a combined Zenodo deposit at
\href{https://doi.org/10.5281/zenodo.20292792}{doi:10.5281/zenodo.20292792}
(v1.0.0, published 2026-05-18).  The deposit
holds the source-code archive
(\texttt{fhir\_rag\_code\_v0.1.0.zip}, SHA-256
\texttt{b822642131914994e6dd509641bbfaeca}\linebreak[1]\texttt{848556423ae16fa0635278c6eb78ab4}),
and the synthetic dataset archive (\texttt{fhir\_rag\_dataset\_v1.zip}, SHA-256
\texttt{000c27a42d4a304d71e59b700e7209fce}\linebreak[1]\texttt{7edccbbbae7458a1671e8ffe7ce421d}).
A public GitHub repository will accompany the version of record; the
Zenodo archive is the canonical citation for reproducibility purposes.  The revision
analyses added in this version (N/A stratification, cluster bootstrap, output-budget
audit, post-think re-scoring) are produced by
\path{analysis/run_revision_reanalysis.py} and \path{analysis/run_postthink_rescore.py}
and will be included in the next deposit version.

all 1{,}203 input files; overall SHA-256:\\
\texttt{4d0da93e19c3071414ef5e1045d338104f}\linebreak[1]\texttt{9628842abe34f548aa050e9d0aa736}.
The v2 manifest \texttt{data/freeze\_v2.json} adds the 20 revision-arm
artefacts; overall v2 SHA-256:\\
\texttt{2358e8284338f5f52b66b1b9972fd8811}\linebreak[1]\texttt{c625cda829b0ed128c784fdf617deb7}.
No raw model output was regenerated for the present revision; every number in
\S\ref{sec:results} is recomputed from the frozen raw JSONL files.

\paragraph{Raw evaluation JSONLs.}
The raw evaluation files (\path{results/raw_large/a.jsonl},
\path{results/raw_large/b.jsonl}, \path{results/raw_large/c.jsonl},
\path{results/raw_noretrieval/n.jsonl},
\path{results/raw_templated/a_templated.jsonl}, and the three files under
\path{results/raw_1024/}) are not checked into the git repository (too large for GitHub).
They contain the complete model responses, including the \texttt{<think>} blocks and the
billed token counts on which the output-budget audit relies.  All can be regenerated by:
\begin{verbatim}
python -m eval.harness --system {a|b|c} --concurrency 4
python scripts/run_no_retrieval_arm.py --concurrency 4
python scripts/run_templated_arm.py --concurrency 4
python scripts/token_sweep_1024.py --system {a|b|c}
\end{verbatim}
\noindent Regeneration requires (a) a Groq API key with Developer-plan access
and (b) the corresponding cache directory to be populated (cached responses are
gitignored but preserve byte-reproducibility; absent cache, the harness will
recompute at API cost and Groq's serving stack may have changed).  Cache directories:
\texttt{eval/cache/} (canonical A/B/C), \texttt{eval/cache\_noretrieval/},
\texttt{eval/cache\_templated/}, \texttt{eval/cache\_1024/}.

\paragraph{Scoring and statistics.}
All downstream artefacts are reproducible from the raw JSONLs:
\begin{itemize}
  \item Scoring (canonical A/B/C): \texttt{python -m eval.score}
    $\rightarrow$ \path{results/scored.csv}.  Note that \path{scored.csv} stores the
    first 500 characters of each response only; analyses that depend on the full
    response must read the raw JSONL.
  \item Scoring (no-retrieval): \texttt{python -m eval.score --raw-dir results/raw\_noretrieval/}
    \texttt{--output-dir results/scored\_noretrieval/ --systems n}
  \item Question-level statistics: \texttt{python} \path{analysis/run_stats.py}
    $\rightarrow$ \path{analysis/results.md}
  \item Revision analyses (N/A stratification, cluster bootstrap, budget audit):
    \texttt{python} \path{analysis/run_revision_reanalysis.py}
    $\rightarrow$ \path{analysis/revision_reanalysis.md}
  \item Post-think re-scoring: \texttt{python} \path{analysis/run_postthink_rescore.py}
    $\rightarrow$ \path{results/scored_postthink/scored.csv}
  \item Templated-arm comparison: \texttt{python} \path{analysis/run_templated_compare.py}
    $\rightarrow$ \path{analysis/templated_compare.md}
  \item Feature arm: \texttt{python} \path{features/run_feature_arm.py}
    $\rightarrow$ \path{analysis/feature_extraction.md}
\end{itemize}

\paragraph{Model identifiers.}
Narrative generation: \texttt{llama-3.3-70b-versatile} (Meta, via Groq free tier);
prompt hash \texttt{518bc71d87b7}.
Answer generation: \texttt{qwen/qwen3-32b} (Alibaba, via Groq Developer plan);
temperature 0.0, single run per question, Groq default reasoning settings (thinking
enabled, inline \texttt{<think>} block).
Embedding: \texttt{BAAI/bge-large-en-v1.5} (BAAI, via sentence-transformers, local CPU).

\paragraph{Hardware and environment.}
Embeddings and feature extraction: CPU (no GPU required).
Evaluation: Groq API (HTTP; local orchestration only).
Python 3.11; dependencies pinned in \texttt{requirements.txt}.
A Dockerfile is provided for environment reproducibility.
