\section{Reproducibility}
\label{sec:reproducibility}

\paragraph{Code and dataset release.}
Code, dataset, and analysis scripts are released as a combined Zenodo deposit at
\href{https://doi.org/10.5281/zenodo.20263384}{doi:10.5281/zenodo.20263384}
(v1.0.0, published 2026-05-18).  The deposit
holds the preprint PDF, the source-code archive
(\texttt{fhir\_rag\_code\_v0.1.0.zip}, SHA-256
\texttt{b822642131914994e6dd509641bbfaeca}\linebreak[1]\texttt{848556423ae16fa0635278c6eb78ab4}),
and the synthetic dataset archive (\texttt{fhir\_rag\_dataset\_v1.zip}, SHA-256
\texttt{000c27a42d4a304d71e59b700e7209fce}\linebreak[1]\texttt{7edccbbbae7458a1671e8ffe7ce421d}).
A public GitHub repository will be published in the version of record; the
Zenodo archive is the canonical citation for reproducibility purposes.

\paragraph{Release tags.}
The dataset is frozen at release tag \texttt{dataset-freeze-v1}; the original
evaluation results are frozen at release tag \texttt{results-freeze-v1}.  The
revisions reported in \S\ref{sec:results:noretrieval} (no-retrieval baseline) and
\S\ref{sec:results:templated} (templated-narrative ablation) plus the
class-weighted feature-arm re-run (\S\ref{sec:results:o6}) are folded in at a new
release tag \texttt{results-freeze-v2}; the original \texttt{results-freeze-v1}
remains intact for byte-reproducibility against the pre-revision preprint.
The original freeze manifest \texttt{data/freeze.json} records SHA-256 hashes of
all 1{,}203 input files; overall SHA-256:\\
\texttt{4d0da93e19c3071414ef5e1045d338104f}\linebreak[1]\texttt{9628842abe34f548aa050e9d0aa736}.
The v2 freeze manifest \texttt{data/freeze\_v2.json} adds the 20 revision-arm
artifacts (templated and no-retrieval raw outputs and scored CSVs;
class-weighted feature-arm outputs; revision-specific analysis markdown);
overall v2 SHA-256:\\
\texttt{2358e8284338f5f52b66b1b9972fd8811}\linebreak[1]\texttt{c625cda829b0ed128c784fdf617deb7}.

\paragraph{Raw evaluation JSONLs.}
The three canonical raw evaluation files (\path{results/raw_large/a.jsonl},
\path{results/raw_large/b.jsonl}, \path{results/raw_large/c.jsonl}) are not
checked into the git repository (too large for GitHub).  The two revision arms
add \path{results/raw_noretrieval/n.jsonl} (no-retrieval baseline) and
\path{results/raw_templated/a_templated.jsonl} (templated-narrative ablation),
also held locally.  All five files can be regenerated by:
\begin{verbatim}
python -m eval.harness --system {a|b|c} --concurrency 4
python scripts/run_no_retrieval_arm.py --concurrency 4
python scripts/run_templated_arm.py --concurrency 4
\end{verbatim}
\noindent Note: regeneration requires (a) a Groq API key with Developer-plan access
and (b) the corresponding cache directory to be populated (cached responses are
gitignored but preserve byte-reproducibility; absent cache, the harness will
recompute at API cost).  Cache directories: \texttt{eval/cache/} (canonical
A/B/C), \texttt{eval/cache\_noretrieval/}, \texttt{eval/cache\_templated/},
\texttt{eval/cache\_1024/} (the 1024-token sweep).

\paragraph{Scoring and statistics.}
All downstream artefacts are reproducible from the raw JSONLs:
\begin{itemize}
  \item Scoring (canonical A/B/C): \texttt{python -m eval.score}
    $\rightarrow$ \path{results/scored.csv}
  \item Scoring (no-retrieval): \texttt{python -m eval.score --raw-dir results/raw\_noretrieval/}
    \texttt{--output-dir results/scored\_noretrieval/ --systems n}
  \item Statistics: \texttt{python} \path{analysis/run_stats.py}
    $\rightarrow$ \path{analysis/results.md}
  \item Tier-3 recall breakdown: \texttt{python} \path{analysis/run_tier3_recall_breakdown.py}
    $\rightarrow$ \path{analysis/tier3_recall_breakdown.md}
  \item Templated-arm comparison: \texttt{python} \path{analysis/run_templated_compare.py}
    $\rightarrow$ \path{analysis/templated_compare.md}
  \item Error taxonomy: \texttt{python} \path{analysis/run_error_taxonomy.py}
    $\rightarrow$ \path{analysis/error_taxonomy.md}
  \item Feature arm: \texttt{python} \path{features/run_feature_arm.py}
    $\rightarrow$ \path{analysis/feature_extraction.md}
\end{itemize}

\paragraph{Model identifiers.}
Narrative generation: \texttt{llama-3.3-70b-versatile} (Meta, via Groq free tier);
prompt hash \texttt{518bc71d87b7}.
Answer generation: \texttt{qwen/qwen3-32b} (Alibaba, via Groq Developer plan);
temperature 0.0, single run per question.
Embedding: \texttt{BAAI/bge-large-en-v1.5} (BAAI, via sentence-transformers, local CPU).

\paragraph{Hardware and environment.}
Embeddings and feature extraction: CPU (no GPU required).
Evaluation: Groq API (HTTP; local orchestration only).
Python 3.11; dependencies pinned in \texttt{requirements.txt}.
A Dockerfile is provided for environment reproducibility.
